[#ISRC9_V2-Functions]
==== Functions

[.contract-item]
[[ISRC9_V2-execute_from_outside_v2]]
==== `[.contract-item-name]#++execute_from_outside_v2++#++(outside_execution: OutsideExecution, signature: Span<felt252>,) → Array<Span<felt252>>++` [.item-kind]#external#

Allows anyone to submit a transaction on behalf of the account as long as they have the relevant signatures.

This method allows reentrancy. A call to `\\__execute__` or `execute_from_outside_v2` can trigger
another nested transaction to `execute_from_outside_v2` thus the implementation MUST verify
that the provided `signature` matches the hash of `outside_execution` and that `nonce` was
not already used.

The implementation should expect version to be set to 2 in the domain separator.

Arguments:

- `outside_execution` - The parameters of the transaction to execute.
- `signature` - A valid signature on the {snip12} message encoding of `outside_execution`.

[.contract-item]
[[ISRC9_V2-is_valid_outside_execution_nonce]]
==== `[.contract-item-name]#++is_valid_outside_execution_nonce++#++(nonce: felt252) → bool++` [.item-kind]#external#

Get the status of a given nonce. `true` if the nonce is available to use.

[[AccountComponent-set_public_key]]
==== `[.contract-item-name]#++set_public_key++#++(ref self: ContractState, new_public_key: felt252, signature: Span<felt252>)++` [.item-kind]#external#

Sets a new public key for the account. Only accessible by the account calling itself through `\\__execute__`.

Requirements:

- The caller must be the contract itself.
- The signature must be valid for the new owner.

Emits both an {OwnerRemoved} and an {OwnerAdded} event.

[NOTE]
====
The message to be signed is computed in Cairo as follows:

```javascript
let message_hash = PoseidonTrait::new()
        .update_with('StarkNet Message')
        .update_with('accept_ownership')
        .update_with(get_contract_address())
        .update_with(current_owner)
        .finalize();
```
====

==== Verifier strategies

`Falcon512SignatureVerifier` defines the compile-time verification strategy used by the component.
Its `verify` function authenticates a message hash and its `is_valid_public_key` function validates
the packed public-key encoding.

`Falcon512ShakeVerifier` accepts a 60-felt signature containing 29 felts for `s1`, 2 salt felts, and
a 29-felt polynomial-product hint. `Falcon512ShakeDirectVerifier` accepts 29 felts for `s1` and 2
salt felts, and recomputes the polynomial product on-chain.

==== Felt encoding

Each 29-felt polynomial represents 512 coefficients in `Z_q`, where `q = 12289`. Each of the first
28 felts stores 18 coefficients in two 128-bit halves. The low half contains the first nine
coefficients and the high half contains the next nine, with each half encoded as
`c0 + q(c1 + q(c2 + ... + q*c8))`. The final felt stores eight coefficients in its low half and
requires a zero high half. Public keys use the verifier's NTT-domain coefficient order.

Each signature salt felt must be smaller than `2^160`. The two felts encode the 40-byte Falcon salt
as two consecutive 20-byte little-endian limbs. Hash-to-point absorbs those limbs followed by the
message hash encoded as 32 little-endian bytes.

IMPORTANT: Build the deployable Falcon presets from this repository with
`scarb --release build -p openzeppelin_presets`. The workspace dev profile produces Falcon Sierra
artifacts that cannot be lowered to CASM. Only the workspace's `target/release` Falcon preset
artifacts are suitable for declaration. Consumer projects that embed the component must likewise
use a declaration profile with inlining enabled.

have the relevant signatures.

This method allows reentrancy. A call to `\\__execute__` or `execute_from_outside_v2` can
trigger another nested transaction to `execute_from_outside_v2`. This implementation
verifies that the provided `signature` matches the hash of `outside_execution` and that
`nonce` was not already used.

Arguments:

- `outside_execution` - The parameters of the transaction to execute.
- `signature` - A valid signature on the {snip12} message encoding of
`outside_execution`.

Requirements:

- The caller must be the `outside_execution.caller` unless 'ANY_CALLER' is used.
- The current time must be within the `outside_execution.execute_after` and `outside_execution.execute_before` span.
- The `outside_execution.nonce` must not be used before.
- The `signature` must be valid.

```cairo
use openzeppelin_presets::Falcon512ShakeDirectAccountUpgradeable;
```

Upgradeable Falcon-512 account using SHAKE-256 hash-to-point and a 31-felt signature. It recomputes
the polynomial product on-chain and supports owner-authorized key rotation and outside execution
through xref:#SRC9Component[SRC9].
